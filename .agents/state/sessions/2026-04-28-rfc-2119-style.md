# Apply RFC 2119 wording to skill constraints.

## Summary

This session tightened the repository's agent-facing guidance so that high-signal constraints use RFC 2119 keywords consistently. The work started by updating the root guidance in `AGENTS.md` and refreshing `README.md`, then rewrote existing skill files and their reference documents to express hard requirements and recommendations with `MUST`, `SHOULD`, `MUST NOT`, and `MAY`. The result is a more uniform instruction set for agents, with stronger emphasis on non-guessing behavior, plain Markdown output, and selective use of RFC 2119 wording.

## Notes

- Use RFC 2119 keywords selectively for hard constraints; explanatory context reads better when left in normal prose.
- Root guidance and skill-specific guidance should reinforce each other, but the repo-level rule belongs in `AGENTS.md` and not in every sentence of every document.
- Output-format rules and non-guessing rules are especially valuable in skills that generate user-facing Markdown artifacts.
- Reference documents benefit from the same style when they define inclusion rules, portability limits, or hard prohibitions.
